# Dental Flashcards

Personal study app for dental practice. Single-user; no auth. Three sections, swipeable / tab-switchable as horizontal panels:

1. **Cards** — spaced-repetition flashcard feed (FSRS).
2. **First Principles** — core truths from the Oxford Handbook of Clinical Dentistry, organised by chapter, with verbatim source citations one tap away.
3. **Guidelines** — workflows and first principles distilled per organisation (SDCEP, DBOH, BSP, FGDP). Each guideline category contains practical step-by-step workflows (with a slideshow Test mode) and a pooled set of first principles.

## Stack

- Next.js 16 + React 19 (App Router) — see `AGENTS.md` re: API drift from older Next.js
- Drizzle ORM against Neon Postgres (`@neondatabase/serverless`) — only for flashcards
- `ts-fsrs` for scheduling — wrapped in [lib/fsrs.ts](lib/fsrs.ts)
- Tailwind v4
- First Principles and Guidelines are file-based (JSON in `data/`), no DB

## Commands

- `npm run dev` — dev server
- `npm run db:generate` — generate migration from [lib/db/schema.ts](lib/db/schema.ts)
- `npm run db:migrate` — apply migrations via [scripts/migrate.ts](scripts/migrate.ts)
- `npm run db:studio` — Drizzle Studio
- `npm run import` — ingest JSON from `flashcards-import/` into Postgres (idempotent; deduped by SHA-256 of `question + answer` per folder)

## Card content rule

Every card's `answer` must include the **reasoning**, not just the fact. The user has to recall the "why" to pass. See [flashcards-import/README.md](flashcards-import/README.md) for the JSON format the importer expects.

## First Principles (`data/first-principles/`)

One JSON file per Oxford Handbook chapter. The shape:

```ts
type ChapterData = {
  chapter: string;
  slug: string;
  order: number;
  coreTruths: {
    id: string;             // "<chapter-slug>-NNN"
    title: string;
    broaderContext?: string; // ≤30 words, no citations, third person
    body: string;            // "## Heading\n\nparagraph [1]…\n\n## Heading…"
    citations?: { id: number; quote: string; paragraph?: number; source?: string }[];
  }[];
};
```

`paragraph` is the `[index]` from `source-material/oxford-handbook/full-text.txt`. Citations are **verbatim**.

`data/first-principles/index.json` lists chapters; `progress.json` tracks extraction state.

Generated by the **`extract-first-principles`** skill — see `.claude/skills/extract-first-principles/SKILL.md` for the full extraction rules (notebook voice, broaderContext caps, headed-paragraph body structure, verbatim citation rule).

API: `GET /api/first-principles` (index), `GET /api/first-principles/[slug]` (chapter).

## Guidelines (`data/guidelines/`)

One JSON file per organisation: `sdcep.json`, `dboh.json`, `bsp.json`, `fgdp.json`. Each holds **two parallel artefacts** distilled from every source document inside that organisation:

```ts
type GuidelineDetail = {
  slug: string;            // "sdcep", "dboh", "bsp", "fgdp"
  title: string;
  organisation: string;
  order: number;
  description: string;
  workflows: {
    id: string;            // "<slug>-<workflow-name>", unique inside the file
    title: string;
    overview: string;      // plain prose walkthrough (paragraphs separated by \n\n)
    slides: { id: number; title: string; body: string }[];
  }[];
  firstPrinciples: CoreTruth[];  // same shape as Oxford Handbook coreTruths
};
```

`workflows[*].overview` is the calm read; `workflows[*].slides` are leading-statement slides for the Test mode (slideshow). Both describe the same workflow.

`firstPrinciples[]` follows the **same notebook rules** as the Oxford Handbook first principles. Citations use the `source` field (free text like `"SDCEP MRONJ guidance, p.12"`) instead of `paragraph`.

`data/guidelines/index.json` lists categories; `progress.json` tracks state.

Generated by the **`extract-guidelines-slides`** skill — see `.claude/skills/extract-guidelines-slides/SKILL.md`.

API: `GET /api/guidelines` (index), `GET /api/guidelines/[slug]` (full category).

## UI architecture

[app/page.tsx](app/page.tsx) is a horizontal panel container with three panels (Cards, First Principles, Guidelines). [components/bottom-tabs.tsx](components/bottom-tabs.tsx) drives navigation; the panel container scrolls via `scrollIntoView`.

Each panel takes `absolute inset-0` inside its `position: relative` panel wrapper. Bottom sheets (filter drawer, citation sheet, reference sheet) use `position: fixed` so they layer above the bottom tabs.

The First Principles core-truth list and citation sheet live in [components/principle-toggles.tsx](components/principle-toggles.tsx) and are reused inside both [components/first-principles-page.tsx](components/first-principles-page.tsx) and the First Principles sub-toggle of [components/guidelines-page.tsx](components/guidelines-page.tsx).

The Guidelines page uses a four-level toggle hierarchy:
1. **Category** (e.g. SDCEP) — dark-gray toggle, lazy-loads the category JSON on open
2. **Workflows / First Principles** — two sub-toggles inside an open category
3. **Individual workflow** (inside Workflows) — bordered toggle
4. **Overview / Test** (inside an open workflow) — Overview is a toggle that reveals plain prose; Test is a button that switches the page to the slideshow player view

Toggle state is stored as a single `Set<string>` of expanded IDs, so the whole hierarchy can persist while the user enters and leaves the player.

## Data model (flashcards)

Two-level folder tree → cards → per-card FSRS `card_state` + append-only `reviews` log. `settings` is a single-row table holding Telegram chat id, timezone, and notification windows. Schema in [lib/db/schema.ts](lib/db/schema.ts).

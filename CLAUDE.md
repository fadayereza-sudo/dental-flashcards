# Dental Flashcards

Personal study app for dental practice. Single-user; no auth. Three sections, swipeable / tab-switchable as horizontal panels:

1. **Cards** — spaced-repetition flashcard feed (FSRS).
2. **Troubleshoot** — dental troubleshooting guide for clinical decision support. Three-level accordion: **origin → problem → details** (etiology / presentation / results / defining characteristics / treatment / prognosis / condition name). The L2 label is symptom-led — opening it is a "guess the diagnosis" practice; the condition name is revealed inside the L3 panel.
3. **Guidelines** — workflows and first principles distilled per organisation (SDCEP, DBOH, BSP, FGDP, IADT, orthodontic referral). Each category is split into **subjects** (e.g. SDCEP → MRONJ, anticoagulants, child caries…); every subject has its own step-by-step workflows (with a slideshow Test mode) and its own first principles.

**First Principles** data and API live on at `data/first-principles/` and `/api/first-principles/` but are no longer surfaced in the UI — the middle panel was swapped to Troubleshoot. The data is kept for possible later reuse.

## Stack

- Next.js 16 + React 19 (App Router) — see `AGENTS.md` re: API drift from older Next.js
- Drizzle ORM against Neon Postgres (`@neondatabase/serverless`) — only for flashcards
- `ts-fsrs` for scheduling — wrapped in [lib/fsrs.ts](lib/fsrs.ts)
- Tailwind v4
- Troubleshooting, First Principles, and Guidelines are file-based (JSON in `data/`), no DB

## Commands

- `npm run dev` — dev server
- `npm run db:generate` — generate migration from [lib/db/schema.ts](lib/db/schema.ts)
- `npm run db:migrate` — apply migrations via [scripts/migrate.ts](scripts/migrate.ts)

## Card content rule

Every card's `answer` must include the **reasoning**, not just the fact. The user has to recall the "why" to pass. See [flashcards-import/README.md](flashcards-import/README.md) for the JSON format the importer expects.

## Troubleshooting (`data/troubleshooting/`)

The middle panel of the app. One JSON file per **origin** (anatomical or thematic category: `permanent-dentition`, `periodontal`, `tongue`, `lifestyle`, etc.). The 15 canonical origins are: skin, lips, cheeks, tongue, floor-of-mouth, palate, throat, muscles, periodontal, primary-dentition, permanent-dentition, fixed-prosthesis, removable-prosthesis, psychological, lifestyle.

```ts
type OriginData = {
  slug: string;
  title: string;
  order: number;
  description?: string;
  problems: {
    id: string;                      // "<origin-slug>-NNN"
    description: string;             // L2 toggle label — symptom-led one-liner, never names the condition
    conditionName: string;           // revealed inside L3
    etiology: string;                // markdown body, may include [N] citation markers
    presentation: string;
    results: string;
    definingCharacteristics: string;
    treatment: string;
    prognosis: string;
    citations?: { id: number; quote: string; paragraph?: number; source?: string }[];
  }[];
};
```

`citations[].source` is **mandatory** (the citation popout renders this label). `paragraph` is included when the source is paragraph-indexed (`oxford`, `odells`). Every `[N]` marker in the body must resolve to a citation entry. The seven body fields are composed into a single rendered body in [components/troubleshooting-page.tsx](components/troubleshooting-page.tsx) using `## Etiology\n\n…` blocks plus a final `## Name of condition\n\n**{conditionName}**`, so the existing `PrincipleToggleList` handles the rendering and citation popout.

Body markdown supports: `##` section headings (auto-prepended by the page wrapper), paragraphs separated by `\n\n`, bullet lists (`- ` prefixed lines), and `**bold**` inline.

`data/troubleshooting/index.json` lists origins; `progress.json` tracks state.

Generated by the **`extract-troubleshooting`** skill — see `.claude/skills/extract-troubleshooting/SKILL.md`. Prose voice must follow `.claude/skills/writing-style/SKILL.md`.

API: `GET /api/troubleshooting` (index), `GET /api/troubleshooting/[slug]` (origin).

## First Principles (`data/first-principles/`) — dormant in UI

One JSON file per Oxford Handbook chapter. The shape:

```ts
type ChapterData = {
  chapter: string;
  slug: string;
  order: number;
  coreTruths: {
    id: string;             // "<chapter-slug>-NNN"
    title: string;
    broaderContext?: string; // ≤30 words, no citations, third person
    body: string;            // "## Heading\n\nparagraph [1]…\n\n## Heading…"
    citations?: { id: number; quote: string; paragraph?: number; source?: string }[];
  }[];
};
```

`paragraph` is the `[index]` from `source-material/oxford-handbook/full-text.txt`. Citations are **verbatim**.

`data/first-principles/index.json` lists chapters; `progress.json` tracks extraction state.

Generated by the **`extract-first-principles`** skill — see `.claude/skills/extract-first-principles/SKILL.md` for the full extraction rules (notebook voice, broaderContext caps, headed-paragraph body structure, verbatim citation rule).

API: `GET /api/first-principles` (index), `GET /api/first-principles/[slug]` (chapter).

## Guidelines (`data/guidelines/`)

One JSON file per category: `sdcep.json`, `dboh.json`, `bsp.json`, `fgdp.json`, `iadt.json`, `orthodontic-referral.json`. Each category is partitioned into **subjects**, and every subject holds its own workflows and first principles:

```ts
type GuidelineDetail = {
  slug: string;            // "sdcep", "dboh", "bsp", "fgdp", "iadt", "orthodontic-referral"
  title: string;
  organisation: string;
  order: number;
  description: string;
  subjects: {
    slug: string;          // unique within the category (e.g. "mronj", "child-caries")
    title: string;
    order: number;
    description?: string;
    workflows: {
      id: string;          // "<category-slug>-<workflow-name>", unique across the whole file
      title: string;
      overview: string;    // markdown manual: ## headings, ### sub-headings, bullets, **bold**
      slides: { id: number; title: string; body: string }[];
    }[];
    firstPrinciples: CoreTruth[];  // same shape as Oxford Handbook coreTruths
  }[];
};
```

Subjects are derived from the source documents (e.g. SDCEP's six source guidance PDFs map to six subjects) or by clinical theme when one source covers many topics (e.g. DBOH → caries-prevention, periodontal, smoking-alcohol, oral-cancer, tooth-wear).

`workflows[*].overview` is the calm read (rendered with [components/manual-markdown.tsx](components/manual-markdown.tsx)); `workflows[*].slides` are leading-statement slides for the Test mode (slideshow). Both describe the same workflow.

`firstPrinciples[]` follows the **same notebook rules** as the Oxford Handbook first principles. Citations use the `source` field (free text like `"SDCEP MRONJ guidance, p.12"`) instead of `paragraph`.

`data/guidelines/index.json` lists categories; `progress.json` tracks state.

Generated by the **`extract-guidelines-slides`** skill — see `.claude/skills/extract-guidelines-slides/SKILL.md`.

API: `GET /api/guidelines` (index), `GET /api/guidelines/[slug]` (full category, including all subjects).

## UI architecture

[app/page.tsx](app/page.tsx) is a horizontal panel container with three panels (Cards, Troubleshoot, Guidelines). [components/bottom-tabs.tsx](components/bottom-tabs.tsx) drives navigation; the panel container scrolls via `scrollIntoView`.

Each panel takes `absolute inset-0` inside its `position: relative` panel wrapper. Bottom sheets (filter drawer, citation sheet, reference sheet) use `position: fixed` so they layer above the bottom tabs.

The core toggle list and citation sheet live in [components/principle-toggles.tsx](components/principle-toggles.tsx) and are reused across [components/troubleshooting-page.tsx](components/troubleshooting-page.tsx), the dormant [components/first-principles-page.tsx](components/first-principles-page.tsx), and the First Principles sub-toggle of [components/guidelines-page.tsx](components/guidelines-page.tsx). The body renderer supports `## headings`, paragraphs (split on `\n\n`), bullet lists (lines prefixed `- ` or `* `), `**bold**` inline, and `[N]` citation markers that open the bottom sheet.

The Guidelines page uses a five-level toggle hierarchy:
1. **Category** (e.g. SDCEP) — dark-gray toggle, lazy-loads the category JSON on open
2. **Subject** (e.g. MRONJ) — medium-gray toggle inside an open category
3. **Workflows / First Principles** — two sub-toggles inside an open subject
4. **Individual workflow** (inside Workflows) — bordered toggle
5. **Overview / Test** (inside an open workflow) — Overview is a toggle that reveals the markdown manual; Test is a button that switches the page to the slideshow player view

Toggle state is stored as a single `Set<string>` of expanded IDs (`cat:<slug>:subj:<subjSlug>:section:workflows`, etc.), so the whole hierarchy can persist while the user enters and leaves the player.
